# 40 - UI 系统（CommonUI / CommonGame / UIExtension / 加载屏 / 前端）

> 引擎版本 UE 5.8。路径相对 `D:/UnrealProjects/LyraStarterGame`。行号来自当前工程源码。

## 1. 职责概述

Lyra 的 UI 由四层机制叠加而成：

1. **CommonGame 插件**：每个本地玩家一个根布局 `UPrimaryGameLayout`，内含若干"层"（`UI.Layer.Game / GameMenu / Menu / Modal`），每层是一个 `UCommonActivatableWidgetContainerBase`（Stack）。所有屏幕都以 `UCommonActivatableWidget` 的形式被 push 到某一层。
2. **UIExtension 插件**：基于 GameplayTag 的"槽位 (Extension Point) / 扩展 (Extension)"发布订阅系统。HUD 布局里放 `UUIExtensionPointWidget`，GameFeature 往 tag 上注册 Widget 类，由槽位自动实例化。
3. **GameFeatureAction_AddWidgets**：Experience / ActionSet 中的数据驱动入口，在 `ALyraHUD` 就绪时把 HUD Layout 推到某层，并把 HUD 元素注册到 UIExtension 槽位。
4. **Lyra 自身 UI C++**：HUD 布局（`ULyraHUDLayout`）、输入模式（`ULyraActivatableWidget`）、确认框（`ULyraUIMessaging`/`ULyraConfirmationScreen`）、世界空间指示器（Indicator System）、前端流程（`ULyraFrontendStateComponent`）、武器准星控件等。

另有 `CommonLoadingScreen`（根据 `ILoadingProcessInterface` 动态决定是否显示加载屏）、`CommonStartupLoadingScreen`（引擎启动 PreLoad 屏）、`AsyncMixin`（Slate/UMG 异步加载辅助）。

## 3. 核心流程与数据流

### 3.1 根布局创建 + HUD 注入

要点：
- 根布局只在拿到 `APlayerController` 后创建（`CreateLayoutWidget` 需要 `LocalPlayer->GetPlayerController`），否则等 `OnPlayerControllerSet`（GameUIPolicy.cpp:53-66）。该 lambda 先 `NotifyPlayerRemoved`（从视口移除）再复用/新建，所以换地图时同一个 Layout 会被重新 AddToViewport。
- `AddToPlayerScreen(1000)`：分屏时每个玩家的根布局独立。
- `ULyraUIManagerSubsystem::Tick` 每帧根据 `AHUD::bShowHUD` 切换根布局可见性（`showhud` 控制台命令会隐藏整个 UI，包括菜单层）。
- 注册是 **ForContext(LocalPlayer)** 的，槽位同时注册了无 context、LocalPlayer context、PlayerState context，所以 HUD 元素只出现在目标玩家的屏幕（分屏正确）。

### 3.2 层模型

`W_OverallUILayout`（`/Game/UI/W_OverallUILayout`，UPrimaryGameLayout 子类）里有四个 `CommonActivatableWidgetStack`，在 `Construct` 里 `RegisterLayer`：

| Tag | 用途 |
|---|---|
| `UI.Layer.Game` | HUD（`W_ShooterHUDLayout` 等） |
| `UI.Layer.GameMenu` | 游戏内与玩法相关的菜单（如背包） |
| `UI.Layer.Menu` | 前端主菜单、暂停菜单(`W_LyraGameMenu`)、设置、手柄断开提示 |
| `UI.Layer.Modal` | 对话框/确认框（`ULyraUIMessaging`） |

各层是独立 Stack；放到上层的 Widget 不会隐藏下层（下层仍可见），但输入配置由最顶部激活的 widget 的 `GetDesiredInputConfig` 决定。`RegisterLayer` 会把 TransitionDuration 设为 0，并在转场时通过 `SuspendInputForPlayer` 临时挂起输入（PrimaryGameLayout.cpp:89-118）。

### 3.3 Push 流程

- 同步：`UCommonUIExtensions::PushContentToLayer_ForPlayer(LP, Tag, Class)` -> `Policy->GetRootLayout(LP)->PushWidgetToLayerStack` -> `Layer->AddWidget`。
- 异步（推荐，软引用）：`PushStreamedContentToLayer_ForPlayer` / BP `UAsyncAction_PushContentToLayerForPlayer`：先 `RequestAsyncLoad` 再 push，期间用 `SuspendInputForPlayer` 过滤 MKB/Gamepad/Touch 输入，完成/取消时 `ResumeInputForPlayer`。
- 弹出：`PopContentFromLayer(Widget)`（遍历所有层）或 Widget 自己 `DeactivateWidget()`。

### 3.4 CommonUI 输入路由与输入模式

- 配置：`Config/DefaultGame.ini` `[CommonInputSettings] InputData=/Game/UI/B_CommonInputData`（默认 Click/Back 动作数据表）；`DefaultInput.ini` `[CommonUIInputSettings] UIActionProcessingPriority=10000`，并定义 `UI.Action.Escape`（Key=Escape / Gamepad_Special_Right）；`bLinkCursorToGamepadFocus=True`、`AnalogCursorSettings` 配置模拟光标。
- `ULyraActivatableWidget::GetDesiredInputConfig`（cpp:16）：Default -> 不覆盖；Game -> `ECommonInputMode::Game` + `GameMouseCaptureMode`(默认 CapturePermanently)；GameAndMenu -> `All`；Menu -> `Menu` + NoCapture。CommonUI 的 ActionRouter 在栈顶变化后采用最顶部激活 widget 的配置。HUD Layout（`W_DefaultHUDLayout`）设为 `GameAndMenu`。
- 动作绑定：Widget 用 `RegisterUIActionBinding(FBindUIActionArgs(...))`。HUD 的 Escape 绑定见 LyraHUDLayout.cpp:39；HUD 失活（被菜单覆盖）后该绑定不再接收输入，菜单里按 Escape 由菜单自身的 Back 动作处理。
- 输入类型：`UCommonUIExtensions::GetOwningPlayerInputType/IsOwningPlayerUsingGamepad/Touch`。`ULyraButtonBase::OnInputMethodChanged` / `ULyraBoundActionButton` 据此切换样式。

### 3.5 前端流程（Frontend）

`B_LyraFrontEnd_Experience`（`/Game/System/FrontEnd/`）是前端 Experience：Actions 包含 `ApplyFrontendPerfSettingsAction`、`AddWidgets`（`HUD.Slot.PerfStats.Text`），并通过 GameState 组件 `B_LyraFrontendStateComponent` 驱动。

`ULyraFrontendStateComponent::BeginPlay`(cpp:28) 以高优先级监听 `ULyraExperienceManagerComponent` 加载完成 -> `OnExperienceLoaded`(cpp:67) 建立 `FControlFlow "FrontendFlow"`，依次：

1. **Wait For User Initialization**(cpp:80)：若 URL 含 `closed`（硬断线）则 `UCommonUserSubsystem::ResetUserState`；总是 `CommonSessionSubsystem::CleanUpSessions`。
2. **Try Show Press Start Screen**(cpp:110)：首个用户已登录则跳过；平台无需 Start 输入(`!ShouldWaitForStartInput`)则自动 `TryToInitializeForLocalPlay`；否则 push `PressStartScreenClass`(`W_LyraStartup`) 到 `UI.Layer.Menu`，其 `OnDeactivated` 时继续流程。
3. **Try Join Requested Session**(cpp:192)：`UCommonGameInstance::GetRequestedSession()` 存在且可加入则 `JoinRequestedSession`，成功则 `CancelFlow`，失败继续。
4. **Try Show Main Screen**(cpp:228)：push `MainScreenClass`(`W_LyraFrontEnd`) 到 `UI.Layer.Menu`，AfterPush 后 `bShouldShowLoadingScreen=false`。

`bShouldShowLoadingScreen` 初始为 true，所以整个前端流程期间加载屏一直显示（原因文本为当前 Flow 步骤名）。

主菜单选择玩法：`ULyraUserFacingExperienceDefinition`（PrimaryDataAsset，目录 `/Game/System/Playlists`、`/Game/UI/Temp`，如 `DA_Frontend`）含 MapID/ExperienceID/ExtraArgs/Tile 文案/`LoadingScreenWidget`/MaxPlayerCount/`bRecordReplay`；`CreateHostingRequest`(GameModes/LyraUserFacingExperienceDefinition.cpp:13) 构造 `UCommonSession_HostSessionRequest`，`ExtraArgs["Experience"]=ExperienceName`。主菜单 BP（`W_LyraFrontEnd`、`W_LyraExperienceTileButton`）拿到它后调用 `CommonSessionSubsystem` 发起 HostSession（C++ 只提供数据与流程骨架，具体按钮逻辑在蓝图）。

### 3.6 加载屏决策

`ULoadingScreenManager::CheckForAnyNeedToShowLoadingScreen`(cpp:255) 按顺序，任一为真即显示：

1. CVar `CommonLoadingScreen.AlwaysShow`；
2. 无 WorldContext / World；
3. `GameState == nullptr`（尚未复制）；
4. `bCurrentlyInLoadMap`（PreLoadMap~PostLoadMap）；
5. `TravelURL` 非空 / `PendingNetGame`；
6. `!World->HasBegunPlay()`；`IsInSeamlessTravel()`；
7. GameState 自身或其组件实现 `ILoadingProcessInterface` 且返回 true（Lyra：`ULyraExperienceManagerComponent`（LoadState != Loaded，"Experience still loading"，GameModes/LyraExperienceManagerComponent.cpp:447）、`ULyraFrontendStateComponent`）；
8. 外部注册的处理器（`RegisterLoadingProcessor`，如 `ULoadingProcessTask`）；
9. 每个本地玩家的 PC 及其组件实现该接口；
10. 分屏需要所有本地 PC 存在，非分屏至少一个本地 PC。

全部通过后，`ShouldShowLoadingScreen`(cpp:407) 还会保持 `HoldLoadingScreenAdditionalSecs`(默认 2s，编辑器内默认不保持) 以待纹理流送，期间强制 `bDisableWorldRendering=false`。

显示时 (`ShowLoadingScreen` cpp:473)：注册输入预处理器吞掉所有输入(非编辑器, cpp:99-123, 640)、广播 `OnLoadingScreenVisibilityChangedDelegate`、创建 `LoadingScreenWidget`(失败退化为 `SThrobber`) 加入视口 ZOrder 10000、`ChangePerformanceSettings`（`bDisableWorldRendering`、ShaderPipelineCache Fast、`bHighPriorityLoadingLocal`、挂起卡顿检测）。隐藏时强制一次 GC。`ULyraAudioMixEffectsSubsystem` 订阅了可见性委托（Audio/LyraAudioMixEffectsSubsystem.cpp:28,216）。

加载屏内容：`W_LoadingScreen_Host`（设置里指定）监听 `ULyraLoadingScreenSubsystem` 的 `OnLoadingScreenWidgetChanged`，显示每个 UserFacingExperience 指定的内容 Widget；`W_LoadingScreenReasonDebugText` 展示 `GetDebugReasonForShowingOrHidingLoadingScreen()`。

启动屏：`CommonStartupLoadingScreen` 在 `PreEarlyLoadingScreen` 阶段注册 PreLoadScreen；`ShowLoadingScreen` 在引擎 PreLoad 屏仍活动时直接返回，`IsShowingInitialLoadingScreen` 时不创建 Widget。若要用启动视频，需禁用该插件。

### 3.7 UIExtension 匹配规则

- 扩展注册时从自身 tag 逐级 `RequestDirectParent` 向上通知：初始 tag 上的槽位总是通知，父 tag 上的槽位仅 `PartialMatch` 才通知（UIExtensionSystem.cpp:210-234）。槽位注册时反向遍历已有扩展（cpp:184）。
- `DoesExtensionPassContract`(cpp:35)：context 必须一致（同为空或同一对象），且 Data 的类（Data 本身是 UClass 时取该类）是槽位 `AllowedDataClasses` 之一的子类/实现。`UUIExtensionPointWidget` 总允许 `UUserWidget`（直接放 Widget 类），额外 `DataClasses` + `GetWidgetClassForData` / `ConfigureWidgetForData` 支持数据驱动。
- `AddWidgets` 注册时用 `LocalPlayer` 作 context，而槽位同时为 LocalPlayer 和 PlayerState 注册了 context。

## 7. 坑与注意事项

1. **`UGameUIManagerSubsystem` 与 `UCommonMessagingSubsystem` 采用"有子类则不创建基类"**（`GetDerivedClasses` 检查）。config 段必须写在子类名下（`LyraUIManagerSubsystem`/`LyraUIMessaging`）；再加一层子类会改变被实例化的类。
2. **根布局依赖 PlayerController**：`CreateLayoutWidget` 没有 PC 时什么也不做，必须等 `ACommonPlayerController::ReceivedPlayer`。自定义 PC 若不继承 `ACommonPlayerController`，UI 永远不会创建。
3. `PushContentToLayer_ForPlayer` 对 `LocalPlayer` 做 `CastChecked<UCommonLocalPlayer>`；Root Layout 尚未创建时返回 nullptr。`AddWidgets` 用同步 push 且用 `LayoutClass.Get()`，**要求类已加载**（靠 `AssetBundles="Client"` 预载），未加载会静默跳过；结果（可能为 null）被加入 `LayoutsAdded`，移除时用 `IsValid` 过滤。
4. `UAsyncAction_PushContentToLayerForPlayer::Activate` 的回调里 `SetReadyToDestroy()` 无条件被调用（cpp:73），上游小瑕疵，不影响使用。
5. **输入挂起令牌**：`SuspendInputForPlayer` 用静态全局递增 `InputSuspensions` 生成唯一 token；异步 push 取消靠 CancelDelegate 恢复，自己写异步逻辑务必成对 Resume。
6. `RegisterLayer` 仅在非 DesignTime 生效；`TransitionDuration` 强制 0（有转场会导致手柄焦点不能正确转移）。
7. **`ULyraUIManagerSubsystem` 每帧隐藏/显示根布局**：`HUD->bShowHUD=false`（`showhud`）会把包含菜单的整个根布局设为 Collapsed。
8. **UIExtension 的 context 机制**：无 context 注册的扩展只会被无 context 槽位接收；`ForContext(LocalPlayer)` 注册的只给对应玩家。传 null context 给 `K2_RegisterExtensionAsWidgetForContext` 会报错并返回空句柄。`RegisterExtensionAsData` 的 Verbose 日志里 `ContextObject` 分支写反了（UIExtensionSystem.cpp:170-177），仅影响日志。
9. `UUIExtensionPointWidget` 在 `ReleaseSlateResources` 中 `ResetExtensionPoint`，Widget 重建会让扩展被销毁重建；`RebuildWidget` 里 `CallAndRegister_OnPlayerStateSet` 返回的 handle 未保存。
10. **GameFeature 停用时**：`RemoveWidgets` 对 Layout 调用 `DeactivateWidget()` 并注销扩展；而 `OnGameFeatureDeactivating -> Reset` 只注销扩展并清空 ActorData，不 deactivate Layout（HUD 实际销毁时才会清理）。
11. `ULyraTaggedWidget` 按 tag 隐藏尚未实现（TODO），不要依赖 `HiddenByTags`。
12. `ULyraHUDLayout` 的手柄断开处理仅在 `Platform.Trait.Input.PrimarlyController` 平台启用（源码与 tag 均为 "Primarly" 拼写，勿"修正"）；编辑器可用 CommonUI 平台模拟 tag 测试。
13. **加载屏**：`GameState==nullptr` 或无本地 PC 都会显示加载屏，自定义 GameMode 若没有 GameState 会一直卡加载屏；隐藏时会 `ForceGarbageCollection`；编辑器内默认不保持 2s 也不吞输入。`ULoadingProcessTask::Unregister` 不做空判断，`Outer` 必须是 LoadingScreenManager。
14. `ULyraFrontendStateComponent` 的 `bShouldShowLoadingScreen` 只在 `AfterPush`/`Canceled` 时清除；`MainScreenClass` 加载异常时加载屏可能一直在。`OnUserInitialized` 失败仅继续流程（TODO）。
15. `ULyraWeaponUserInterface::NativeTick` 每帧轮询装备管理器（非事件驱动）。
16. `PrimaryGameLayout` 的 Dormant 逻辑与 `SingleToggle` 分屏模式基本是桩（`LocalMultiplayerInteractionMode` 默认 PrimaryOnly 且无 setter）。

## 9. 设计意图

**9.1 每玩家根布局 + 分层 Stack（`UPrimaryGameLayout` + `UI.Layer.*`）**
- 解决的问题：分屏/多本地玩家各自需要独立的 UI 树与输入焦点；不同性质的界面（HUD / 局内菜单 / 全屏菜单 / 模态框）需要稳定的叠放顺序，且各自有"返回上一层"的栈语义。
- 机制：`UGameUIPolicy` 为每个 `UCommonLocalPlayer` 创建一个根布局并 `AddToPlayerScreen`；根布局内每层是一个 `UCommonActivatableWidgetContainerBase`（Stack），调用方只需要 "玩家 + 层 tag + Widget 类"，不关心 Slate 层级。
- 朴素做法的后果：直接 `AddToViewport` 会让分屏玩家共享一个全屏层、ZOrder 由各处硬编码互相冲突；没有栈就无法自动恢复下层 Widget 的激活与输入配置（关菜单后 HUD 不会自动重新拿回输入）；模态框可能被后弹出的菜单盖住。

**9.2 UIExtension 槽位而非直接引用 HUD 控件**
- 解决的问题：HUD 内容由"当前 Experience/GameFeature"决定（射击模式有弹药条、其它模式没有），核心 HUD 布局不能硬依赖每个玩法的控件。
- 机制：布局只声明 `UUIExtensionPointWidget(tag)`；GameFeature 通过 `UGameFeatureAction_AddWidgets` 往 tag 上注册 Widget 类（带 LocalPlayer context）；激活/停用时槽位自动增删条目。
- 朴素做法的后果：布局蓝图硬引用所有玩法控件 -> 引用链把所有玩法资源拖进核心包（违背 GameFeature 的可卸载性、增加内存与打包体积）；新增玩法必须改核心布局；GameFeature 卸载后残留悬空 Widget；分屏时无法按玩家定向。context 机制（LocalPlayer/PlayerState）正是为了避免"广播给所有玩家"。

**9.3 CommonUI `UCommonActivatableWidget` + `GetDesiredInputConfig`**
- 解决的问题：游戏/菜单切换时，输入模式（Game/Menu/All）、鼠标捕获、焦点、动作绑定（含手柄/键鼠按键提示）必须随"当前最上层屏幕"一致变化。
- 机制：只有各层栈顶 Widget 激活；`ULyraActivatableWidget::InputConfig` 声明意图，ActionRouter 在栈变化时统一应用；动作绑定随 Widget 激活/失活自动启停（如 HUD 的 Escape 被菜单覆盖后自动失效）。
- 朴素做法的后果：每个菜单手动 `SetInputMode`/`SetShowMouseCursor` 并在关闭时手动恢复，嵌套菜单、异常关闭、多玩家时极易遗留错误输入模式（鼠标消失、输入被吞）；手柄焦点需要手写管理。

**9.4 异步 push + 输入挂起（`PushWidgetToLayerStackAsync`）**
- 解决的问题：菜单类用软引用以免常驻内存，但加载期间玩家可能连按键位造成重复 push。
- 机制：加载期间 `SuspendInputForPlayer`（输入类型过滤），完成/取消后 `ResumeInputForPlayer`；回调分 Initialize（Push 时初始化）/AfterPush。
- 朴素做法的后果：同步加载造成卡顿；不挂输入会出现重复打开同一屏幕；取消路径不恢复会永久锁输入（因此取消委托必须绑定）。

**9.5 加载屏作为"被轮询的接口"（`ULoadingScreenManager` + `ILoadingProcessInterface`）**
- 解决的问题：何时可以撤掉加载屏取决于许多异步事实（地图加载、GameState 复制、Experience 加载、前端流程、用户初始化、PC 存在……），且这些模块互不知晓。
- 机制：管理器每帧轮询：引擎状态检查 + 询问 GameState/其组件/本地 PC/其组件/外部注册者"你还要挡着吗"，全部否定后再多保持 N 秒覆盖纹理流送。任一模块只需实现一个接口并返回原因字符串。
- 朴素做法的后果：事件驱动（谁加载完谁通知）需要一个汇总点，少通知一个就永久卡屏或提前露出未就绪画面；PreLoadMap/PostLoadMap 之间的窗口、无缝旅行、客户端 GameState 未复制等时间窗很难靠事件覆盖；轮询 + 原因字符串还提供了现成的调试能力（心跳日志）。

**9.6 前端用 GameState 组件 + FControlFlow**
- 解决的问题：登录、Press Start、加入被邀请会话、主菜单这些步骤有先后依赖且部分异步、部分平台可跳过。
- 机制：`ULyraFrontendStateComponent` 在 Experience 加载后按步骤队列执行，各步骤 `ContinueFlow/CancelFlow`；同时它是加载屏阻塞者，直到主菜单已 push 才放行。
- 朴素做法的后果：在关卡蓝图/Widget 构造里串联会把平台流程散落各处，且加载屏会在主菜单前提前撤掉导致露出空场景。

**9.7 指示器系统走 Controller 组件 + 描述符 + Slate 画布**
- 解决的问题：世界空间标记要每帧投影、排序、夹边，数量可能很多。
- 机制：`UIndicatorDescriptor`（纯数据）经 `ULyraIndicatorManagerComponent`（挂 Controller，跨 Pawn 存活）进入 `SActorCanvas`，控件对象池复用，绑定接口 `BindIndicator`。
- 朴素做法的后果：每个目标 Actor 自带 WidgetComponent -> 大量 3D Widget 渲染开销、无法统一夹边与排序，且随 Pawn 销毁丢失状态。

## 10. 速查问答

**Q1. 怎么加一个小地图？**
做一个 `UCommonUserWidget` 蓝图（内部用 `URetainerBox`/材质 + 场景捕获或 UMG Canvas，数据来自 `GetOwningPlayerPawn`/GameState）。新增 tag `HUD.Slot.Minimap`，在 HUD 布局（`W_ShooterHUDLayout`，ShooterCore/UserInterface）拖一个 `UIExtensionPointWidget` 并设该 tag；再在目标 Experience 的 ActionSet（如 `LAS_ShooterGame_StandardHUD`）的 `Add Widgets` 动作里加 `{WidgetClass=W_Minimap, SlotID=HUD.Slot.Minimap}`。世界空间标记则用 §6.3 的 `UIndicatorDescriptor`。无需改 C++。

**Q2. HUD 某元素只在某模式显示怎么做？**
把该元素放进该模式的 Experience/ActionSet 的 `Add Widgets` 动作里（`UGameFeatureAction_AddWidgets::Widgets`），不放进通用 ActionSet 即可（例：`HUD.Slot.TeamScore` 只在团队模式的 ActionSet 注册）。运行时动态显隐：在 Widget 内按 GameState/GameplayMessage 控制 Visibility（`ULyraTaggedWidget` 的 tag 隐藏尚未实现，别用）。

**Q3. 为什么菜单打开后鼠标不出现？**
看栈顶 widget 的 `ULyraActivatableWidget::InputConfig`（LyraActivatableWidget.cpp:16）：`Default` 不覆盖输入配置，会沿用 Game 模式；需要鼠标就设 `Menu`（NoCapture）或 `GameAndMenu`。同时确认 widget 是推到 `UI.Layer.Menu` 等层上，而不是普通 `AddToViewport`（后者不经 ActionRouter）。

**Q4. 为什么输入被吞？**
排查顺序：(1) 加载屏可见：`FLoadingScreenInputPreProcessor` 吞掉所有输入（LoadingScreenManager.cpp:99，非编辑器）；(2) 异步 push 期间/层转场期间 `SuspendInputForPlayer` 过滤了输入（PrimaryGameLayout.h:67、PrimaryGameLayout.cpp:107），若取消路径漏了 `ResumeInputForPlayer` 会一直被吞；(3) 栈顶 widget 的 `InputConfig=Menu` 使 Game 输入不转发；(4) `UI.Layer.Modal` 有未关闭的对话框；(5) `UIActionProcessingPriority=10000`（DefaultInput.ini）使 UI 动作优先于游戏。

**Q5. 分屏时 UI 怎么处理？**
每个 `UCommonLocalPlayer` 一个独立 `UPrimaryGameLayout`（`RootViewportLayouts`，GameUIPolicy.h:97），用 `AddToPlayerScreen(1000)` 加到该玩家的视口区域（GameUIPolicy.cpp:129）。UIExtension 通过 `ForContext(LocalPlayer)` 保证 HUD 元素只进对应玩家的槽位。加载屏在 `bEnablePlayersSplitRT` 时为每个玩家单独创建 (LoadingScreenManager.cpp:515)。分屏配置由 `UGameFeatureAction_SplitscreenConfig` 控制。`ELocalMultiplayerInteractionMode` 默认 `PrimaryOnly`，`SingleToggle` 路径基本是桩。

**Q6. 怎么弹一个确认框并拿到结果？**
C++：`LocalPlayer->GetSubsystem<UCommonMessagingSubsystem>()->ShowConfirmation(UCommonGameDialogDescriptor::CreateConfirmationYesNo(H,B), Delegate)`；实际执行 `ULyraUIMessaging::ShowConfirmation` (LyraUIMessaging.cpp:25)，push 到 `UI.Layer.Modal`，调用 `ULyraConfirmationScreen::SetupDialog` (LyraConfirmationScreen.cpp:19)；点击按钮 → `CloseConfirmationWindow` (:72) → `DeactivateWidget` + 回调。蓝图用 `UAsyncAction_ShowConfirmation`。对话框类在 `DefaultGame.ini [LyraUIMessaging]`。

**Q7. 怎么加一个新的 UI 层？**
在 `DefaultGameplayTags.ini` 加 `UI.Layer.Xxx`；打开 `/Game/UI/W_OverallUILayout`，加 `CommonActivatableWidgetStack`，在 Construct 调 `RegisterLayer(UI.Layer.Xxx, Stack)`。`FLyraHUDLayoutRequest::LayerID` 的 Categories 过滤为 `UI.Layer`，新 tag 必须在此命名空间下。

**Q8. 根布局是谁创建的？在哪换成自己的？**
`UGameUIPolicy::CreateLayoutWidget` (GameUIPolicy.cpp:189)。换法：改 `B_LyraUIPolicy.LayoutClass`（`/Game/UI/B_LyraUIPolicy`，继承 `GameUIPolicy`），或在 `DefaultGame.ini [LyraUIManagerSubsystem] DefaultUIPolicyClass` 指向别的 Policy。根布局必须继承 `UPrimaryGameLayout` 且非 Abstract（`ensure` 于 GameUIPolicy.cpp:194）。

**Q9. HUD 元素没出现，怎么排查？**
(1) 日志 `LogUIExtension` Verbose 看 "Extension [...] @ [...] Registered"；(2) HUD 布局里是否有对应 tag 的 `UIExtensionPointWidget`，`ExtensionPointTagMatch` 是否 Exact；(3) Widget 类是否已加载（`AddWidgets` 用 `.Get()`，`AssetBundles="Client"`）；(4) `ALyraHUD::BeginPlay` 是否发出 GameActorReady（GameMode 的 HUDClass 是否为 ALyraHUD，LyraGameMode.cpp:42）；(5) `showhud` 是否关闭；(6) 分屏 context 是否匹配；(7) `DoesExtensionPassContract` 要求 Data 类可赋给 `UUserWidget`。

**Q10. UIExtension 的 ExactMatch 与 PartialMatch 区别？**
槽位注册时 `EUIExtensionPointMatch`：Exact 只收同 tag 扩展；Partial 还收子 tag（如槽位 `HUD.Slot` 收 `HUD.Slot.Reticle`）。实现见 `NotifyExtensionPointsOfExtension` (UIExtensionSystem.cpp:210-234：沿 `RequestDirectParent` 向上，非初始 tag 时仅 Partial 才通知) 与 `NotifyExtensionPointOfExtensions` (:184，Exact 时 break)。

**Q11. 同一个槽位可以放多个控件吗？顺序？**
可以。`UDynamicEntryBoxBase` 为每个扩展 `CreateEntryInternal`；顺序即注册/回放顺序，`Priority` 字段存入 `FUIExtension` 但 `UUIExtensionPointWidget` 并未用它排序。需要排序就自己改 `OnAddOrRemoveExtension` 或在布局中用多个槽位。

**Q12. 怎么让某个 Widget 只给某个玩家的槽位？**
`RegisterExtensionAsWidgetForContext(Tag, ContextObject=LocalPlayer/PlayerState, Class, Priority)`。槽位对三种 context 注册：无、`GetOwningLocalPlayer()`、`APlayerState`（UIExtensionPointWidget.cpp:90-113）。用 PlayerState 做 context 可实现按玩家数据（如队伍）定向。

**Q13. 如何让某屏幕按 ESC 关闭而不是再打开暂停菜单？**
屏幕自身用 `RegisterUIActionBinding` 绑定 Back 动作并 `DeactivateWidget()`（参考 `ULyraSettingScreen::NativeOnInitialized`，LyraSettingScreen.cpp:13-20）。栈顶只有该屏幕激活，HUD 的 `UI.Action.Escape` 绑定不会触发。

**Q14. 怎么在 C++ 里给指定玩家 push 屏幕？**
`UCommonUIExtensions::PushContentToLayer_ForPlayer(LocalPlayer, Tag, Class)` 或 `PushStreamedContentToLayer_ForPlayer(LP, Tag, SoftClass)`（后者异步）。在 Widget 内用 `GetOwningLocalPlayer()`。需要 `#include "CommonUIExtensions.h"` 且模块依赖 `CommonGame`。

**Q15. 怎么拿到某玩家的根布局？**
`UPrimaryGameLayout::GetPrimaryGameLayout(APlayerController*)` / `(ULocalPlayer*)` / `GetPrimaryGameLayoutForPrimaryPlayer(WorldContext)` (PrimaryGameLayout.cpp:17-45)，或 `UCommonLocalPlayer::GetRootUILayout()` (CommonLocalPlayer.cpp:70)。

**Q16. 怎么给角色头顶加名牌/交互提示？**
走指示器系统：`ULyraGameplayAbility_Interact::UpdateInteractions` (Interaction/Abilities/LyraGameplayAbility_Interact.cpp:41) 为每个可交互目标 `NewObject<UIndicatorDescriptor>`，`SetIndicatorClass(InteractionWidgetClass)`，`ULyraIndicatorManagerComponent::AddIndicator`。名牌见 `/Game/UI/Indicators/NameplateManagerComponent`、`W_Nameplate`。显示由 HUD 里的 `UIndicatorLayer` → `SActorCanvas::UpdateCanvas` (SActorCanvas.cpp:158) 每帧投影。

**Q17. 指示器在屏幕外怎么处理？**
`SetClampToScreen(true)` 时，`SActorCanvas::OnArrangeChildren` (cpp:311) 把位置夹到屏幕内边距矩形，`SetShowClampToScreenArrow(true)` 则绘制箭头（`SActorCanvasArrowWidget`，使用 `UIndicatorLayer::ArrowBrush`）；在摄像机后方时 `FIndicatorProjection::Project` 把位置推到屏幕边缘 (IndicatorDescriptor.cpp:40-44)。

**Q18. 如何阻塞加载屏直到某个异步初始化完成？**
见 §6.5：让 GameState 组件实现 `ILoadingProcessInterface::ShouldShowLoadingScreen`（返回 true 并写 Reason），或 `ULoadingProcessTask::CreateLoadingScreenProcessTask`。`CheckForAnyNeedToShowLoadingScreen` (LoadingScreenManager.cpp:326-349) 每帧会询问。

**Q19. 如何更换每个玩法的加载屏内容？**
`ULyraUserFacingExperienceDefinition::LoadingScreenWidget`（GameModes/LyraUserFacingExperienceDefinition.h:53）；前端 BP 在进入前调用 `ULyraLoadingScreenSubsystem::SetLoadingScreenContentWidget` (LyraLoadingScreenSubsystem.cpp:18)；宿主 `W_LoadingScreen_Host`（`DefaultGame.ini [CommonLoadingScreenSettings] LoadingScreenWidget`）监听变更并换内容。C++ 中没有任何地方调用该 setter，调用点在蓝图。

**Q20. 编辑器里看不到加载屏或感觉很短？**
`HoldLoadingScreenAdditionalSecs` 在编辑器默认不生效 (LoadingScreenManager.cpp:442)；`ForceTickLoadingScreenEvenInEditor=False`（DefaultGame.ini）导致不强制 Slate Tick；输入预处理器在编辑器 `CanEatInput()==!GIsEditor` 不吞输入。用 `CommonLoadingScreen.AlwaysShow 1` 调试。

**Q21. 前端 Press Start 屏什么时候出现？**
`FlowStep_TryShowPressStartScreen` (LyraFrontendStateComponent.cpp:110)：首用户已登录则跳过；`UCommonUserSubsystem::ShouldWaitForStartInput()` 为 false（PC 通常如此）则自动登录；只有需要 Start 输入的平台才 push `PressStartScreenClass`。

**Q22. 如何从外部邀请直接进房间？**
平台覆盖层 → `UCommonSessionSubsystem::OnUserRequestedSessionEvent` → `UCommonGameInstance::OnUserRequestedSession` (CommonGameInstance.cpp:129) → `SetRequestedSession` (:150)：`CanJoinRequestedSession` 为真则 `JoinRequestedSession` (:172)，否则 `ResetGameAndJoinRequestedSession` (:190) 回主菜单；前端流程第 3 步 `FlowStep_TryJoinRequestedSession` 接手。

**Q23. 手柄断开屏何时弹出？**
`ULyraHUDLayout::NativeOnInitialized` 在 `ShouldPlatformDisplayControllerDisconnectScreen` 为真（平台特征含 `Platform.Trait.Input.PrimarlyController`）时订阅 `IPlatformInputDeviceMapper` 连接/配对变更 → `NotifyControllerStateChangeForDisconnectScreen` (LyraHUDLayout.cpp:117) 下一帧 → `ProcessControllerDevicesHavingChangedForDisconnectScreen` (:134)：若该平台用户无已连接手柄 → `DisplayControllerDisconnectedMenu` (:175) push 到 Menu 层。

**Q24. 按键提示图标怎么随重绑定更新？**
`ULyraActionWidget::GetIcon` (Foundation/LyraActionWidget.cpp:12)：若设置了 `AssociatedInputAction`，用 EnhancedInput `QueryKeysMappedToAction` 取实际按键，再经 `UCommonInputPlatformSettings::TryGetInputBrush` 取图标；否则回落到 CommonUI 数据表默认键。

**Q25. 设置界面从哪里创建数据？**
`ULyraSettingScreen::CreateRegistry` (LyraSettingScreen.cpp:22) → `NewObject<ULyraGameSettingRegistry>` + `Initialize(ULyraLocalPlayer*)`；Apply/Cancel 绑定仅在 `OnSettingsDirtyStateChanged_Implementation` 为 dirty 时 `AddActionBinding` (:56-73)。

**Q26. 想在 HUD 里做可点击控件（鼠标）？**
HUD 布局 `InputConfig=GameAndMenu` 才允许 UI 同时接收；触屏用 `ULyraTouchRegion`/`ULyraJoystickWidget`（`ULyraSimulatedInputWidget` 向 `UEnhancedPlayerInput` 注入）。根布局默认可见性是 `SelfHitTestInvisible` (LyraUIManagerSubsystem.cpp:60)，HUD 子控件需自行设为 Visible 才能被点击。

**Q27. 准星/命中标记怎么挂？**
`HUD.Slot.Reticle` 槽位挂 `W_WeaponReticleHost`（ShooterCore，`LAS_ShooterGame_StandardHUD`）；内部用 `ULyraReticleWidgetBase` 子类（`InitializeFromWeapon` 获取 `ULyraWeaponInstance`，`ComputeSpreadAngle`/`ComputeMaxScreenspaceSpreadRadius` 驱动 `UCircumferenceMarkerWidget::SetRadius`）与 `UHitMarkerConfirmationWidget`（Slate `SHitMarkerConfirmationWidget`）。`ULyraWeaponUserInterface::NativeTick` (Weapons/LyraWeaponUserInterface.cpp:28) 轮询当前武器并触发 `OnWeaponChanged`。

**Q28. 异步加载 widget 时如何避免 this 悬空？**
继承 `FAsyncMixin`（AsyncMixin.h:72）：`CancelAsyncLoading(); AsyncLoad(SoftClass, [this]{...}); StartAsyncLoading();`，回调保证按序且 owner 销毁后不再调用。`SActorCanvas::AddIndicatorForEntry` (SActorCanvas.cpp:562) 就是示例。

**Q29. 如何让 UI 在 GameFeature 卸载时自动清理？**
通过 `AddWidgets` 注册即可：`Reset`/`RemoveWidgets` 自动 `Unregister` 扩展（HUD 销毁时还会 `DeactivateWidget` 布局）。自己手写的话要保存 `FUIExtensionHandle` 并在卸载时 `Unregister()`。

**Q30. 为什么在 PIE 里 UI 偶尔不获得手柄焦点？**
`UGameUIPolicy::OnRootLayoutAddedToViewport` (GameUIPolicy.cpp:151) 仅在编辑器对主玩家 `SetUserFocusToGameViewport(0)`；屏幕若没实现 `GetDesiredFocusTarget`，`ULyraActivatableWidget::ValidateCompiledWidgetTree` 会在编译时给出警告 (LyraActivatableWidget.cpp:34-49)。另外层转场时长被强制为 0 就是为了避免焦点丢失 (PrimaryGameLayout.cpp:97)。
